## Main findings

1. **Seguridad está fuerte.** Los intentos de prompt injection y cruce de tenant fueron bloqueados correctamente.
2. **RAG informacional básico funciona.** Las preguntas de “cómo hacer X” salieron bien.
3. **Reportes están en riesgo.** Los dos casos de reportes devolvieron cero actividad, posiblemente inconsistente con la operación observada hoy.
4. **Legal está roto.** Las preguntas normativas no están cubiertas y una incluso fue mal clasificada como reporte.
5. **Acciones están seguras pero poco guiadas.** No ejecutan cambios sin confirmación, pero el flujo conversacional todavía es incompleto.

## Recommended diagnosis / likely root causes

- **Intent router con cobertura insuficiente** para consultas legales/normativas.
- **RAG corpus incompleto** o embeddings/prompts orientados solo a manual operativo del sistema, no a conocimiento legal-operativo.
- **Resolver de reportes por fecha/turno** posiblemente consultando una fuente vacía, turno incorrecto o timezone incorrecto.
- **Action orchestration** prioriza “lookup fallo” antes de correr un flujo de confirmación más humano.

## Priority fixes

1. Corregir consulta de reportes “hoy” y “top vendidos hoy”; validar contra datos reales del restaurante.
2. Agregar intent/corpus para preguntas legales: NOM-251, Distintivo H y otras normas sanitarias frecuentes.
3. Mejorar acciones para pedir confirmación estructurada incluso cuando falten datos, por ejemplo orden, motivo, autorización.
4. Agregar smoke tests automáticos que comparen reportes contra una fuente conocida antes de responder.
